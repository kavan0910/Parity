Platform contract (hosted product)

Single source of truth shared by the parallel workstreams. Implements product-architecture.md Phases 1 to 3, except billing: no payment provider, no checkout, no invoices. Billing stays a BillingProvider interface with a NoBilling implementation (decision deferred by the owner).

Workstreams and owned directories (do not edit another stream's directory):

Stream Owns Depends on
A. Engine seams src/migration_agent/ (new service.py, storage.py; minimal edits elsewhere), tests/ for those nothing
B. Backend backend/ migration_agent.service (section 2)
C. Web web/ HTTP API (section 3)
D. Ops, security, docs deploy/, docs/security/, .github/workflows/, root *.md additions paths of A, B, C

1. Repository layout

src/migration_agent/        engine (library + CLI), stays pip-installable and CLI-compatible
backend/                    FastAPI service + worker (own pyproject.toml, own venv at backend/.venv)
web/                        Next.js (App Router, TypeScript, Tailwind)
deploy/                     docker-compose for the full stack, Dockerfiles, env templates
docs/security/              data-handling, retention, subprocessor list, SOC 2 readiness checklist

2. Engine service API (migration_agent.service, stream A)

Pure functions over a local project directory (the existing folder layout). No HTTP, no database, no network other than the configured model endpoint. All must be importable without the llm extra unless an LLM is used.

class StageResult(BaseModel):
    stage: str                        # ingest | extract | analyze | verify | resolve, or a Phase 2 stage (below)
    status: Literal["ok", "stopped_budget", "failed"]
    summary: dict                     # stage specific counts (nodes, edges, findings, chunks ...)
    cost_usd: float
    error: str | None = None

Event = dict   # {"type":"progress","stage":str,"done":int,"total":int}
               # {"type":"usage","stage":str,"task":str,"model":str,"input_tokens":int,"output_tokens":int,"usd":float}
               # {"type":"log","level":str,"message":str}

def review_state(project_dir: Path) -> dict        # same shape the review UI serves at /api/state
def graph_snapshot(project_dir: Path, version: int | None = None) -> dict   # {"version","nodes":[...],"edges":[...]}
def graph_versions(project_dir: Path) -> list[dict]

Rules: on_event is called from worker threads safely; budget is enforced inside the engine (max_usd); the engine never reads credentials from the process environment when config carries an explicit api_key; llm allows tests to inject FakeLLM/OfflineLLM; the CLI keeps working unchanged; the existing tests stay green.

Phase 2 stages (self-hosted only)

run_stage also accepts the Phase 2 stages below (service.P2_STAGES). Each needs an approved migration contract (the stage fails with the gate error otherwise). Spend is capped by max_usd and by what remains of the project budget in target/target.yaml (migrate/ledger.py). offline=True uses the deterministic offline clients. Stage-specific inputs go in options. Expected failures come back as status="failed"; a budget stop as stopped_budget.

Stage Does options summary keys
target_fit target-fit analysis -> target/fit_report.json|md none risks, by_severity, needs_decision, dropped_unverified, model_calls, blockers
plan slice plan -> plan/migration_plan.json|md dry_run, name_with_model version, slices, dry_run, excluded_nodes, plan_blockers, warnings, estimate_usd
tests tests generate; optionally records against a running legacy service node_ids, record_url, record_url2 created, kept, dropped, needs_approval, provisional, nodes; with record_url: recorded, record_issues
generate slice generation loop (runs exec jobs) slice_id (default: all slices), max_usd_per_slice, max_iterations, from_comments outcomes, warnings, awaiting_human
equivalence legacy vs new per slice, in plan order (in-network exec jobs unless URLs are given or the harness reports host URLs) slice_id, legacy_url, new_url, triage slices (cases, equivalent, pct, regressions, unknown per slice), unexplained
cutover readiness + cutover/plan.md; optional approval approve, by, note ready, blockers, warnings, approval, plan; with approve: approved (refused while not ready -> failed)

There is no metrics stage: call service.metrics(project_dir). Harness, recording against the sandbox, flips, slice approvals and config/schema commands are CLI only.

Hosted mode does not run Phase 2. Decision P2-Q13: Phase 2 is CLI/self-hosted only. The hosted worker (backend/app/worker.py) runs only ingest, extract, analyze, verify and resolve, and must not run Phase 2 stages: generate and equivalence (without URLs) start exec containers, and tests with record_url calls a running legacy service. The worker holds database credentials and is not a credential-free exec runner. run_stage itself does not enforce this; the caller must.

3. HTTP API (/v1, stream B implements, stream C consumes)

JSON, ids are UUID strings, timestamps ISO-8601 UTC, auth Authorization: Bearer <jwt>. Errors: {"error":{"code":"string","message":"string"}} with proper status codes (401, 403, 404, 409, 422, 429). Lists: {"items":[...],"total":int} with limit (default 50, max 200) and offset. A resource of another workspace is always answered with 404, never 403, to avoid leaking existence.

Area Endpoint Notes
Health GET /healthz, GET /readyz no auth
Auth POST /v1/auth/signup, POST /v1/auth/login, GET /v1/me AUTH_MODE=dev (password, local JWT) or oidc (verify external JWT via JWKS; users are created on first sight)
Workspaces GET/POST /v1/workspaces, GET /v1/workspaces/{wid}, GET/POST /v1/workspaces/{wid}/members, DELETE .../members/{uid} roles: owner, admin, member, viewer
Projects POST/GET /v1/workspaces/{wid}/projects, GET/PATCH/DELETE /v1/projects/{pid} DELETE removes every artifact, cache entry and row, writes an audit record
Source POST /v1/projects/{pid}/source (multipart zip/tar.gz or JSON {"git_url":"https://..."}) git URL: https only, public hosts only, block private/link-local/loopback (SSRF), size caps
User docs POST/GET/DELETE /v1/projects/{pid}/user-docs for the Verifier only
Estimate POST /v1/projects/{pid}/estimate {chunks, usd, allowed, reason} using the engine dry-run and the entitlement check
Runs POST /v1/projects/{pid}/runs (202), GET /v1/projects/{pid}/runs, GET /v1/runs/{rid}, POST /v1/runs/{rid}/cancel, GET /v1/runs/{rid}/events (SSE) body {type: analyze|verify|reanalyze, model_profile: fast|balanced|best, max_usd, incremental}; status: queued, running, succeeded, failed, stopped_budget, cancelled
Results GET /v1/projects/{pid}/graph (version,type,q,limit,offset), .../graph/nodes/{nid}, .../graph/versions, .../graph/diff?a=&b=, .../document, .../changelog, .../export?format=md|json|html
Review GET /v1/projects/{pid}/findings, POST .../findings/{fid}/resolution, GET/POST .../comments resolution status: accepted_doc, accepted_code, dismissed, needs_reanalysis; needs_reanalysis and accepted_doc enqueue a reanalyze run
Usage GET /v1/workspaces/{wid}/usage?from=&to=, GET /v1/workspaces/{wid}/entitlements totals and per run; plan, limits, consumption
Audit GET /v1/workspaces/{wid}/audit admins only

model_profile maps server-side to engine model configs; customers never choose raw model ids.

Response shapes (verified end to end by scripts/e2e_local.sh and a real-mode browser run)

All timestamps ISO-8601 UTC. Errors always {"error":{"code","message"}}; validation failures are 422 invalid_request, unsafe sources 422 invalid_source, plan limits 403 entitlement_denied, missing prerequisites 409 (no_source, no_analysis, run_in_progress), oversized bodies 413. Lists take limit (1..200, default 50) and offset.

  • Auth. POST /v1/auth/signup body {email, password (10..256 chars), display_name?} returns 201, POST /v1/auth/login body {email, password} returns 200; both answer {access_token, token_type:"bearer", expires_in, user}. Signup creates a default workspace (owner). user = {id, email, display_name, created_at}. GET /v1/me = user fields plus workspaces:[{id,name,role,created_at}]. The web client copies display_name to name.
  • Workspace {id, name, created_at, role}. Member {user_id, email, display_name, role, created_at}; POST .../members body {email, role} (the user must already have an account) returns 201 with a member.
  • Project {id, workspace_id, name, description, created_at, updated_at, source, estimate, last_run, source_kind ("none"|"git"|"upload"), source_ref, last_run_status, node_count, open_findings}. node_count and open_findings are null until the first successful run. Create body {name, description?}; PATCH {name?, description?}; DELETE 204.
  • Source. POST /v1/projects/{pid}/source, 201, answers the source (not the project): {id, kind:"git"|"upload", git_url, sha256, bytes, file_count, created_at}. Upload is multipart/form-data with the single field file (zip, tar.gz); git is JSON {git_url} (https only, public hosts, port 443). A new source replaces the old one and clears the stored estimate. GET returns the same shape (404 when none).
  • Estimate (200, synchronous) {chunks, usd, allowed, reason}; body {model_profile?, max_usd?, incremental?}.
  • Run {id, project_id, workspace_id, type, status, model_profile, max_usd, incremental, cost_usd, estimate_usd, engine_version, error, current_stage, completed_stages, cancel_requested, created_at, started_at, finished_at}. POST .../runs answers 202 (200 when an Idempotency-Key replays an existing run).
  • SSE GET /v1/runs/{rid}/events (Authorization: Bearer, read with fetch streaming; ?after=<seq> or Last-Event-ID replays). Each message is id: <seq>, event: <type>, data: <json payload without "type">. Types: status ({status} where status is running, retrying, cancel_requested, a terminal status, ...), stage ({stage, status:"started"|"done"}), progress ({stage, done, total}), usage ({stage, task, model, input_tokens, output_tokens, usd}), log ({level, message}), and a final event: end with {status} (the run's terminal status). Comment lines : ping are heartbeats.
  • Graph GET .../graph = {version, total, items:[node], edges:[edge touching returned nodes]} (items = the page; total = matches before paging). Node {id, type, name, module, qualified_symbol, responsibility, evidence:[{file, line_start, line_end, symbol, quote}], quirk, suspected_bug, confidence}. Node detail {version, node, edges, neighbours}. Versions {items:[{version, node_count, edge_count}], total}. Diff {a, b, added_nodes, removed_nodes, changed_nodes: [{id, name, type}], added_edges, removed_edges, changed_edges (counts)}.
  • Document / changelog answer text/markdown (plain body, not JSON); 404 until a run produced one. Export is a download (Content-Disposition); format=json is {project, graph, versions, findings}.
  • Finding (the engine review shape) {id, kind, severity, title, detail, item_ids, quotes:[{source, text, anchor, verified}], area, resolution, comment_count}; resolution is null or {status, note, author, created_at}. POST .../findings/{fid}/resolution body {status, note?, model_profile?, max_usd?} answers 201 {resolution, run, run_denied_reason}; run is the queued reanalyze run for needs_reanalysis/accepted_doc.
  • Comment {id, item_id, text, author, author_id, created_at}; item_id is a graph/doc id or a finding id.
  • Usage {from, to, totals:{input_tokens, output_tokens, usd, events, runs}, by_run:[{run_id, project_id, project_name, type, input_tokens, output_tokens, usd, at}], by_model:[...]}. Entitlements {plan, limits:{max_projects, max_members, max_runs_per_month, max_concurrent_runs, max_usd_per_run, monthly_usd_budget, max_source_mb}, consumption:{projects, members, runs_this_month, active_runs, usd_this_month}}. Audit item {id, workspace_id, actor, action, target, at, meta}.
  • CORS. Set CORS_ORIGINS (comma list) to the web origin; allowed methods GET/POST/PATCH/DELETE, headers Authorization, Content-Type, Idempotency-Key, no credentials (bearer tokens only).

4. Data model (stream B, Postgres in production, SQLite in tests)

workspaces, users, memberships(role), projects, sources, user_docs, runs(status, type, profile, max_usd, cost_usd, engine_version, started_at, finished_at, error), run_events(seq, type, payload), artifacts(run, kind, key, sha256, bytes), usage_events(workspace, project, run, stage, task, model, input_tokens, output_tokens, usd, at), plans(name, limits json), entitlements(workspace, plan, overrides json), audit_log(actor, action, target, at, meta), jobs(queue table: id, run_id, status, locked_by, locked_at, attempts, available_at).

Tenancy: every project-scoped query filters by the caller's workspace membership in one shared dependency; no route builds its own filter. Postgres deployments additionally enable row-level security keyed on workspace_id.

5. Worker (stream B)

python -m app.worker: claims jobs (FOR UPDATE SKIP LOCKED on Postgres, equivalent on SQLite), materialises the project from storage into a scratch dir, calls migration_agent.service.run_stage per stage, streams events into run_events and usage_events, uploads artifacts, enforces the per-run budget and entitlements, retries with backoff, is idempotent per run, and always cleans the scratch dir. The model API key is injected per job from server configuration, never stored in a project.

Storage interface ObjectStore (put, get, delete_prefix, list) with LocalStore (dev, tests) and an S3Store skeleton behind the same interface. Keys are prefixed {workspace_id}/{project_id}/. LLM cache is per workspace.

6. Billing-agnostic seam (stream B)

BillingProvider protocol (ensure_customer, sync_plan, report_usage) and NoBilling (no-ops). can_start_run( workspace, estimate) is the only place plan limits are enforced. Default plan internal is generous. No payment code, SDK, keys, webhooks or pricing numbers anywhere.

7. Web (stream C)

Next.js App Router, TypeScript strict, Tailwind. Pages: landing (whole-product description; approval and Phase 2 are CLI-only), sign up / log in, dashboard (projects), new project (connect git URL or upload), project overview (runs, estimate, start run with live progress via SSE), understanding document, graph explorer (search, filter by type, node detail with evidence quotes and confidence, version diff), findings review (resolve, comment), usage and plan, workspace members, settings (delete project/data). Typed API client generated by hand from section 3 with one module (web/lib/api.ts). NEXT_PUBLIC_API_MOCK=1 serves realistic fixtures so the whole UI can be demoed and tested without the backend. Accessible, responsive, light and dark. npm run build, npm run lint and npm run typecheck must pass.

8. Ops, security, docs (stream D)

deploy/docker-compose.yml (postgres, backend, worker with egress allowlist proxy, web), Dockerfiles for backend and web, .env.example, a smoke script, CI jobs for backend and web, docs/security/ (data handling and retention, subprocessors, incident response outline, SOC 2 readiness checklist, secure SDLC), an operations runbook, and updates to README and CHANGELOG. No claims of certifications that do not exist.

9. Definition of done

Each stream: tests pass locally, no secrets committed, nothing outside its owned directories modified (except stream A's engine and the CHANGELOG/README entries by D), a short NOTES.md in its directory listing what was built, what is deliberately not built, and open problems.
