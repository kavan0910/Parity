Phase 2 architecture: the migrate/ package

Companion to phase2-plan.md (the agreed plan, decisions in its section 14). This page describes the code as it is: the module map, the public functions, the shared contracts, and how to add commands. User-level instructions are in user-guide.md section 9; security controls in threat-model.md section 9.

Status: milestones M0 to M7 are implemented and tested offline (unit and integration tests with a scripted docker CLI and fake model clients). They have also run on a real Docker daemon on the eval fixtures, without a model: see the "Implementation status" section at the top of the plan and remaining-work.md for what has and has not run live.

Model rules worth knowing: - CharacterizationCase: expect.source == "specified" only with decision == "fix"; the request shape must match kind. A specified expectation gates a slice only once expect.approved_by is set (tests approve-spec). - ExecJob: command is argv; phase test requires network none; env values that look like secrets (ingest secret patterns) are rejected, use synthetic_secrets; mount sources are project-relative without .., mount targets absolute container paths.

ID prefixes (migrate/ids.py)

Format PREFIX-NNNN (4+ digits), never reused or renumbered, stored in migration/ids.json.

Prefix Meaning Typical key
SLICE migration slice sorted node ids of the slice (re-planning the same nodes keeps the id)
CT characterization test case <target>/<category>/<title-slug>
RISK target-fit risk kind:item_ids
EQ equivalence diff or runtime finding eq:<case_id>/<field>, runtime:<CT>:<kind>
RUN one sandbox exec run or one recording pass none (sequential)

Phase 1 IDs (COMP-, EP-, RULE- ..., F- findings, CM- comments) keep their own registries. Phase 2 comments in migration/comments.json also use CM- ids, in their own sequence.

The plan's tests/ folder is named characterization/ so it is not confused with a repository's own tests. Methods taking ids (slice_dir, case_file, run_dir ...) validate them, so a crafted id cannot escape the folder. Write files with state.atomic_write_json / atomic_write_text (they create parent folders); call layout.ensure(dir) once for the folder so the schema bump happens.

Entry gate and budget

  • require_contract(project, pin=..., accept_unmapped=...) returns the MigrationContract or raises ContractError (with .check). check_contract returns ContractCheck{ok, errors, warnings, blockers, graph_version, latest_graph_version, contract_sha256, pinned} and implements plan section 1 rules 1-7 (listed in contract.py). blockers lists deferred findings (finding_id, item_ids); the planner attaches them to slices.
  • Model calls get their budget from ledger.budget_for(project, spec.budget_usd, max_usd=cli_max_usd): an llm.litellm_client.Budget capped at the remaining project budget (sum of llm_call audit records), so caps hold across sessions. The slice runner tags model calls with slice=SLICE-NNNN (TaggedAudit); Ledger.by_slice gives per-slice spend, checked before every call against --max-usd-per-slice.

Slice state machine (migrate/state.py)

planned -> tests_recorded -> generating -> built -> tests_passing -> reviewed -> awaiting_human -> approved | rejected
fix loop: built | tests_passing | reviewed | awaiting_human -> generating   (iteration += 1; generating -> generating too)
rejected -> generating | planned        approved -> generating (reopen, e.g. human commit)
any except approved -> blocked (reason required); blocked -> the status it came from | planned

transition(project, slice_id, to_status, actor=..., reason=...) validates (raises IllegalTransition), locks, writes atomically and audits (slice_runner / slice_transition). Slice.status in the plan is only a mirror.

CLI registration pattern (migrate/cli.py)

cli.py has one line: from .migrate.cli import register as _register_phase2; _register_phase2(main). register(main) creates the groups contract, target, tests, harness, config, adds the M0 commands (contract check, contract schema, doctor), then imports each name in SUBMODULES and calls its register(groups). Listed names: target, fit, planner, harness, testgen, recorder, slice_runner, codegen, equivalence, approvals, configmap, schemacompat, cutover, metrics. Top-level verbs (plan, generate, equivalence, approve-slice, reject-slice, slice, cutover, metrics) go on groups.main. A missing module is skipped; an import error inside an existing module propagates. Keep heavy imports inside command functions.

ExecBackend contract (migrate/exec/)

class ExecBackend(Protocol):
    name: str
    def available(self) -> tuple[bool, str]: ...    # cheap, no side effects (used by `doctor`)
    def run(self, job: ExecJob) -> ExecResult: ...  # never raises for job failures
  • One job = one disposable container; job.command is argv.
  • Network: none (mandatory for test), or mirror (build only: per-run --internal network plus a Squid proxy that allows only the configured mirror hosts; no hosts configured means --network none).
  • Limits from job.limits (cpus, memory_mb, pids, timeout_s, disk_mb), plus cap_drop ALL, no-new-privileges, non-root, read-only rootfs + tmpfs, no docker socket, --runtime runsc when installed or required.
  • Images are never pulled (--pull never); they are resolved locally and run by image ID.
  • No secrets: validated env; synthetic_secrets filled with fresh random values per run.
  • exec/policy.py checks the job and the final argv before every start.
  • Results are files under runs/RUN-NNNN/ written by record_run (1 MB log cap, redaction, audit record exec/exec_run).
  • get_backend(project) returns DockerBackend(project). Tests inject FakeExecBackend by monkeypatching migration_agent.migrate.exec.get_backend.

Configuration: harness/mirror.json {"hosts": [...], "ports": [443], "runtime": "auto", "proxy_image": ..., "user": "auto"}; MA_MIRROR_HOSTS (comma separated) overrides hosts; MA_EXEC_RUNTIME (auto|runsc|runc) overrides runtime.
