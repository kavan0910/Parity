Threat model (D-06)

Scope: the migration-agent CLI, its project folder, the ingestion engine, the analysis/verification pipeline, the local review server, and the container sandbox. Verified by the red-team suite in tests/redteam/ (fixtures built at test time by scripts/make_redteam.py; inert payloads in eval/redteam/payloads.json). Run: PYTHONPATH=src .venv/bin/python -m pytest -q tests/redteam.

1. Assets

Asset Why it matters
Customer source code and its history Proprietary IP; must only leave the machine as redacted prompt text to the one model endpoint.
Credentials embedded in the customer repo (cloud keys, tokens, DB passwords, private keys) Highest-impact leak: must never reach a prompt, trace, cache, checkpoint, graph, doc or review UI.
Operator credentials (ANTHROPIC_API_KEY in env/.env) Spend and account abuse. Never written to disk by the tool; scrubbed from audit free text if echoed.
Integrity of the knowledge graph / understanding doc Wrong or attacker-authored "facts" mislead a migration. Every claim must carry verifiable evidence.
Host filesystem and network of the analyst's machine Must not be readable/writable/reachable through repo content.
Review state (feedback/*.json, token) Reviewer decisions drive re-analysis; token grants write access to the UI.

2. Actors

Actor Capability
A1 Malicious repo author Controls every byte of the source (files, names, comments, archives, git metadata). Primary adversary.
A2 Hostile model output / prompt-injected model Returns arbitrary JSON; may try to cite files outside the repo or invent graph items.
A3 Malicious web page in the reviewer's browser Can make cross-origin requests to 127.0.0.1, attempt DNS rebinding and CSRF.
A4 Malicious or careless user-doc author Pastes credentials or injection text into user_docs/ or review comments.
A5 Network observer / compromised dependency Watches or redirects egress. Partly out of scope (see residual risks).
A6 Co-resident local user Reads project folders or the review port. Out of scope beyond loopback binding and a per-run token.

Boundaries that carry a control: (B1) source -> ingest/; (B2) code/ -> prompts; (B3) prompts -> network; (B4) model output -> graph; (B5) browser -> review server; (B6) process -> host (container).

4. Network egress allowlist

Exactly two destinations are permitted; everything else is denied by construction or by the container.

# Destination When Mechanism
E1 Git remote named by the operator (https, ssh, file only) init/ingest of a git URL, once ingest._git_clone: GIT_ALLOW_PROTOCOL=https:ssh:file, protocol.allow=never baseline, ext::/git:///http:///ftp:// rejected before any process starts. Local paths, zips and tarballs never spawn git.
E2 The configured model endpoint, via the allowlisting proxy analyze, verify, resolve --reanalyze without --offline LiteLLMClient -> litellm.completion only. Container model profile: worker on an internal: true network; Squid (docker/squid.conf) permits CONNECT to one dstdomain on 443 and deny all.

Loopback traffic to the review server (127.0.0.1, random port) is local only. --offline analysis, init, extract, render, audit, changelog and archive/dir ingest open no sockets and spawn no processes (test_egress.py). The in-process guard (sandbox/guard.py) can enforce the same allowlist inside a worker as defense in depth.

5. Secrets handling

  1. Redact at the choke point. ingest/secrets.py::redact_text runs on every copied file. Patterns: AWS access keys, GitHub tokens, Slack tokens, Stripe sk_/rk_ keys, Google API keys, JWTs, URL-embedded passwords, key/secret/password/token = value assignments, and multi-line PEM private-key blocks. Values become [REDACTED:<kind>]; surrounding code is preserved so structure and line numbers stay valid.
  2. Credential files are withheld, not copied: .env, .env.* (except *.example|sample|template|dist), id_rsa/ed25519/..., *.pem, *.key, *.p12, *.jks, .netrc, .npmrc, .pgpass, ... They appear in IngestReport.exclusions (secret_file) and as findings listing the kind only.
  3. Findings never contain the value (SecretFinding.preview is the line with placeholders). ingest_report.json therefore is safe to share.
  4. Because code/ is already redacted, everything derived from it (facts, inventory, prompts, llm_cache/, checkpoint/, graph snapshots, understanding.latest.md, graph.html, review state) is redacted too.
  5. Defense in depth at the other sinks: AuditLog.record redacts all string fields (error messages, commands); the verifier redacts user docs and the understanding doc before prompting; the review server and review.comments/resolutions redact comment/note/author text before it is stored or sent to re-analysis.
  6. The operator API key lives only in the process environment; it is not written to the project folder (test_nothing_secret_in_any_prompt_trace_cache_or_artifact sets it and scans every artifact).

7. Residual risks (accepted or open)

  1. Redaction is pattern-based. A novel or low-entropy secret (a human-chosen password in a variable not named password/secret/token/key, a bare high-entropy string) will be sent to the model. Mitigation: review ingest_report.json, extend PATTERNS, consider an entropy detector. Redacted placeholders are best-effort.
  2. Prompt injection is mitigated, not solved. Delimiters and instructions raise the bar; the hard guarantee comes from the output gate (schema + deterministic evidence verification + path containment). An injected model can still make true-but-misleading claims (e.g. mislabel a rule) that cite real lines, or lower quality of analysis. Human review of the doc is the control.
  3. analyze/crossref.fence and gapfill use their own <<<DATA ... DATA>>> fence that only defangs the exact ASCII markers (no homoglyph/zero-width handling); render()-based prompts are fully neutralised. Follow-up: route fence() through neutralize.
  4. ReadOnlyTools.grep accepts model-supplied regex: catastrophic backtracking (ReDoS) is bounded only by file and line caps. Not currently reachable from LLM output, but a future tool-calling loop must add a timeout/re2.
  5. No api_base in LLMConfig. Model destination is whatever LiteLLM resolves (provider default or env); the hard egress guarantee is the container proxy (single dstdomain), not application code. The proxy allows by domain name, so DNS or the model host itself is a covert channel; pin the narrowest host.
  6. In-process guard is a tripwire, not a boundary (ctypes/native code bypass); the container is the boundary. Docker profiles are reviewed but were not exercised in CI.
  7. Local review server: a co-resident local user who can read the URL/token (shell history, process list) can act as the reviewer. No TLS (loopback only).
  8. Tree-sitter and document parsers (pypdf, docx XML) process untrusted bytes in-process; a parser bug is a memory-safety/DoS risk. docx XML uses stdlib ElementTree (entity-expansion exposure on very old Pythons); mitigated by the container's memory/pid limits.
  9. Git history is not scanned: only the checked-out tree at --depth 1; secrets in older commits are never fetched. A git remote you choose is trusted for availability, not content.
  10. Already-ingested projects created before redaction hold unredacted code/; re-ingest to apply it.
  11. Comments added by editing feedback/*.json by hand bypass review.comments redaction.
  12. The .env loader reads the tool's .env (operator key). Do not place the operator .env inside an analysed repo.
