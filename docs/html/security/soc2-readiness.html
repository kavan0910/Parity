SOC 2 readiness checklist

This project is NOT SOC 2 compliant, has NOT been audited, and no report exists. This checklist maps the AICPA Trust Services Criteria (Security category first) to what exists and what is missing, to plan a future Type I engagement. Per docs/product-architecture.md, start the formal path once there are customers. Legend: Exists = implemented in this repo; Partial; Missing.

Honest summary

Strong technical groundwork for Security and Confidentiality in the engine (sandboxing, redaction, evidence verification). The platform controls (tenant isolation, audit, deletion, monitoring) are designed but unverified. The organisational controls (policies approved, reviews, vendor management, training, DR) are mostly missing. A Type I readiness assessment is a sensible next step only after the platform is running and the items above are in place.

Update 2026-11-09

A hostile review produced 15 findings and a deploy bug; see pentest-2026-11-09.md. Fixed with regression tests: SSE exhaustion, denial of wallet, tar directory bombs, deletion completeness, invitations, JWT secret strength, rate-limit behind proxy, SSRF gaps, headers/races. Open: F5 (worker holds DB credentials and the model key) and the remainder of F4 (RLS on memberships/audit/entitlements, composite FKs). Postgres hardening (FORCE RLS, role split, append-only audit) is written but unverified. None of this changes the statement that the project is not SOC 2 compliant.
