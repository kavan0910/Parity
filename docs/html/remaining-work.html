What is built, what is verified, and what is left

Last updated 2026-11-15. This page compares the code with every plan that defines the product:

  • the design grill, .lavish/migration-agent-grill.html (Q1 to Q18, Phase 1: understand and verify);
  • the implementation plan, .lavish/migration-agent-impl-plan.html (phases A to D, deliverables A-01 to D-08);
  • the Phase 2 plan, phase2-plan.md (milestones M0 to M7) and the Phase 2 grill outcome in its section 14;
  • the product roadmap, product-architecture.md section 11 (hosted product, phases 0 to 3);
  • the open security findings, security/pentest-2026-11-09.md.

Words are literal. Built means the code exists and offline tests pass. Verified live means it also ran for real: a real Docker daemon, a real service. Unmeasured means it runs but nobody has scored its quality. Nothing here has run with a real model for Phase 2, and nothing has been hand-scored on a large real repository.

Not done, and not code:

  • Accuracy is unmeasured. The plan's own Phase 0 gate (5 to 10 real repositories of 50k to 500k lines, hand-scored precision, evidence validity and coverage, cost per 1k lines) has not run. The only real runs are three repositories of 1.8k to 4.3k lines, each in one chunk, on two different models, with nothing hand-scored. No node reached high confidence. This is the largest open question for the whole product.
  • Scale is tested on synthetic repositories only (D-02 asks for a real 2,000-file repository).
  • The Verifier has not run against real documentation.
  • The signed, versioned release (D-03) needs CI, and CI has never run (see the platform section).

What the live runs found. Every one of these passed all offline tests before it was fixed:

  1. The allowlisting proxy (Squid) crashed on start, so every build that used a package mirror failed with EAI_AGAIN.
  2. Its log directory was not writable by Squid's own user.
  3. Its access log was unreadable, so the egress audit file was empty.
  4. Squid's ICMP helper logged a FATAL on every start (disabled).
  5. The strangler router never started: a tmpfs over the job's working directory hid the image's own /app/proxy.py. The schema probe had the same bug. The backend now refuses any job whose tmpfs would mask a path its command uses.
  6. Codemod jobs had no writable HOME or package cache, /tmp is mounted noexec (tool binaries must be started through their interpreter), Maven ignores HTTPS_PROXY, and js-codemod on npm ships none of the transforms the adapter named. A tool crash was also indistinguishable from "no changes".
  7. The spring-lite fixture did not compile (Member.getId() was missing); Phase 1 only ever read it.
  8. Authenticated services could not be tested at all: the sandbox generated a random API token per run but nothing sent it, and the documented seed_requests replay did not exist. express-crud's 24 recorded cases were nearly all 401. Header injection, seed replay, restart-before-compare and the timestamp rule fix this: the cases now record 14 200s, 8 400s, a 404 and a 204, and the identity port is 24 of 24 equivalent with zero fuzz divergences.

Commercial (roadmap phase 3)

Not started, and gated on real cost numbers from the Phase 0 runs: pricing, a billing provider behind the existing BillingProvider seam, plans, limits and invoices; a public security page; data-processing terms and subprocessor agreements; SOC 2 Type I preparation (a readiness checklist exists); SSO. Later in the roadmap: a self-hosted bring-your-own-key tier, more languages, CI integration (analyse on merge, drift alerts), and an API with webhooks.

Recommended order

  1. Run the plan's Phase 0 gate with a real model: 5 to 10 real repositories, hand-score a sample. Until this exists every claim about quality and every price is a guess, and it unblocks everything below.
  2. Run Phase 2 with a real model on the three fixtures (the live test already covers everything except the model), then on one real service you can build. Read the generated code; record the human-edit rate and cost per slice.
  3. Get CI green, so the Docker tests, the Phase 2 eval gate and the signed release run on every change.
  4. Close F5 (worker isolation) and run the hosted stack once end to end, including Postgres and RLS (F4).
  5. Finish the web screens that the CLI already has (approval, Phase 1 gate, user-docs upload, exports).
  6. Only then decide pricing and billing.
